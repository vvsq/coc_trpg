# 部署文档 — 雾都疑云 · CoC 智能体跑团助手

> 目标：**一台全新的 Windows 电脑，10 分钟内跑起来并开一局**。
> 对应 goal §7 阶段 6.1「部署与分发」。相关决策：D6 单端口部署。

---

## 0. 一句话结论

装好 **Python 3.11+** 和 **Node.js 22 LTS+**，双击仓库根目录的 **`start.bat`**，
浏览器自动打开 `http://127.0.0.1:8000` 即可开团。第一次会花几分钟装依赖、建库、打包前端；
之后每次启动都在 10 秒内。

**不需要** 单独启动前端（没有 5173 端口这回事了 —— 前端产物由后端单端口托管）。

## 1. 环境准备（只做一次）

| 依赖 | 版本要求 | 下载 | 注意 |
| --- | --- | --- | --- |
| Python | **3.11 或更高**（实测 3.12.10） | https://www.python.org/downloads/ | 安装界面务必勾选 **Add python.exe to PATH** |
| Node.js | **22 LTS 或更高**（实测 24.13.0） | https://nodejs.org/ | 装完**重开一个命令行窗口**让 PATH 生效 |
| 操作系统 | Windows 10 / 11 | — | 脚本为 Windows 批处理；Mac/Linux 走第 5 节手动启动 |

装完可以自查（在任意命令行窗口）：

```bat
python -V
node -v
npm -v
```

三条都能打印版本号，就说明环境齐了。

## 2. 一键启动（推荐）

双击仓库根目录的 **`start.bat`**。它会依次做 5 件事，并在窗口里逐条报告进度：

| 步骤 | 做了什么 | 失败时会怎样 |
| --- | --- | --- |
| 0/5 | 检查端口（默认 8000）是否被占用 | 直接告诉你换端口：`start.bat 8080` |
| 1/5 | 检查 Python 版本 ≥ 3.11 | 提示下载地址与 PATH 勾选项 |
| 2/5 | 检查 Node.js 版本 ≥ 22 | 提示下载地址（低版本只警告，不中断） |
| 3/5 | 建 `.venv` 虚拟环境 / 装后端依赖 | 自动用 ensurepip 修残缺 venv；装不上给国内源命令 |
| 4/5 | 补 `backend/.env`、建库或补增量迁移 | 已有数据库只补迁移，**不动房间与存档** |
| 5/5 | 构建前端产物 `frontend/dist` | 类型检查失败会自动回退为仅打包并提醒你 |
| — | 起服务（0.0.0.0:8000）+ 打印局域网地址 + 自动开浏览器 | — |

### 可选参数

```bat
start.bat                  :: 默认 8000 端口，自动开浏览器
start.bat 8080             :: 换端口（端口被占用时的提示就是这个）
start.bat --check          :: 只做环境自检与准备，不起服务（排错 / 演示前预检）
start.bat --rebuild        :: 强制重建前端产物（改过前端代码后必用）
```

`--check` 是演示前的推荐预检：它把所有准备工作做完，然后干净退出，不会占着端口。
`--check` 与 `--rebuild` 都**不做端口预检**（它们本身不起服务），所以服务已经在跑时也能用；
`--rebuild` 重建完成后如果还想顺便启动服务，端口被占用时会给出换端口的提示。

### 想自己控制更多？直接调驱动脚本

`start.bat` 只是纯 ASCII 的引导壳，真正的流程在 `scripts/bootstrap.py`（只用标准库），
也可以直接运行：

```bat
python -X utf8 scripts\bootstrap.py --check
python -X utf8 scripts\bootstrap.py 8080 --no-browser
```

> **为什么中文提示不在 bat 里**（踩坑记录，别再改回去）：cmd.exe 读取 UTF-8 批处理文件时，
> 若在文件内执行了 `chcp 65001`，而控制台初始代码页不是 65001（用户双击就是这种情况，
> 新控制台为 CP936），会发生**行读取错位**——中文注释行的后半截被当成命令执行，实测会报
> `'数据库' is not recognized as an internal or external command`。
> 同一文件在 CP65001 的控制台里运行却完全正常（非确定性）。
> 因此 `start.bat` 保持纯 ASCII 且不调用 `chcp`，中文与全部判断都在 Python 侧，
> 由 `bootstrap.py` 通过 `SetConsoleOutputCP(65001)` 设置控制台编码。

## 3. 局域网开团（多人一起玩）

1. **主机**双击 `start.bat`，启动成功时窗口会打印类似：

   ```
   本机访问：  http://127.0.0.1:8000/
   局域网访问（把这行发给一起跑团的人）：
              http://192.168.1.3:8000/        <-默认网卡
              http://192.168.10.1:8000/
   ```

   **只把 `<-默认网卡` 那一行发给玩家**（其余是 VMware / VPN 的虚拟网卡地址，别人连不上）。

2. 玩家在**同一局域网/WiFi**下用浏览器打开该地址即可，不需要装任何东西。

3. 打不开时按顺序排查：
   - 两台设备是否在同一个 WiFi / 网段；
   - Windows 防火墙首次会弹「是否允许 Python 访问网络」→ 勾选**专用网络**并允许；
     没弹或点错了，去「防火墙和网络保护 → 允许应用通过防火墙」里放行 Python，或临时关闭防火墙试一次；
   - 主机 IP 是否变了（路由器重启后 DHCP 会换 IP）→ 重新看启动窗口打印的地址；
   - 手机连的是「访客网络」通常与主机隔离，换成主网络。

## 4. 配置大模型（可选，不配也能演示）

三种方式，**任选一种**：

| 方式 | 怎么做 | 适合 |
| --- | --- | --- |
| ① 演示模式（零配置） | 启动后大厅顶部会出现引导条，点 **「启用演示模式」** | 现场演示、断网、不想花钱 |
| ② 游戏内配置（推荐） | 大厅 → **「API / 模型配置」** → 填 Base URL / Key / 模型 → **保存** → **测试连通** → 可点**「探测模型」**确认模型名 | 有 Key 的正常使用 |
| ③ 首次 seed | 复制 `project/backend/.env.example` 为 `project/backend/.env` 并填 `LLM_API_KEY` / `LLM_MODEL` | 批量部署 / 脚本化 |

要点：

- **配置权威是数据库**（`llm_config` 表，4.4 起）。`.env` 只在"数据库里还没有配置行"时被读入做一次种子；
  之后改 `.env` 不生效 —— 请在游戏内设置面板改（保存即热重载，无需重启）。
- **Key 永不回传明文**：界面只显示掩码，设置面板留空表示"保持现有 Key"。
- **轻任务模型**（建议生成 / 场景摘要 / 解析修复）只能在设置面板里填，留空 = 跟随主模型。
  填一个便宜快的模型（如 `qwen3.8-flash`）能显著省 token，长团尤其明显。
- 混合推理模型（qwen3 系）建议把**超时**调到 300~600 秒，并确认「思考模式」为关。
- Token 账目在设置面板里看：**全局总账** + **本场消耗**；
  `prompt_tokens` 是名义输入，其中「命中」部分走前缀缓存折扣，看命中率更有意义。
- API Key 属于个人资源，**不要写进任何会被提交的文件**（`.env` 已在 `.gitignore` 里）。

## 5. 手动启动（开发模式，Mac / Linux 也走这条）

前后端两个终端，前端仍走 Vite 代理（改代码热更新最快）：

```bash
# 终端 1：后端（8000）
cd project/backend
python -m venv .venv
# Windows: .venv\Scripts\activate       Mac/Linux: source .venv/bin/activate
pip install -r requirements.txt
python -X utf8 scripts/init_db.py          # 首次建库 + 灌种子数据
python -X utf8 -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

# 终端 2：前端（5173，带 /api 与 /ws 代理）
cd project/frontend
npm install
npm run dev
```

浏览器打开 Vite 打印的地址（默认 `http://localhost:5173`）。
后端 API 文档：`http://127.0.0.1:8000/docs`。

## 6. 常见问题（FAQ）

**Q：端口 8000 被占用？**
按启动脚本提示处理：关掉占用进程，或 `start.bat 8080` 换端口。查占用者：
`netstat -ano | findstr :8000` 拿到 PID 后到任务管理器结束它。

**Q：提示没找到 Python / Node.js？**
基本都是安装时没勾 PATH，或装完没重开窗口。重开一个命令行再试；仍不行就重新安装并勾选 PATH。

**Q：依赖装不上（pip / npm 超时）？**
换国内源重试：

```bat
:: 后端
project\backend\.venv\Scripts\python.exe -m pip install -r project\backend\requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
:: 前端
cd project\frontend && npm config set registry https://registry.npmmirror.com && npm install
```

**Q：前端构建失败？**
窗口会打印 vue-tsc 的类型错误。修完重跑 `start.bat --rebuild`。
只想先跑起来可以手动 `cd project\frontend && npm run build-only`（跳过类型检查，提交前记得补 `npm run type-check`）。

**Q：页面白屏 / 打开是旧界面？**
前端产物没更新：`start.bat --rebuild`。`index.html` 已设 `Cache-Control: no-cache`，正常情况下刷新就能拿到新版本。

**Q：局域网玩家打不开？**
见第 3 节排查顺序（同一网段 → 防火墙放行 → 用 `<-默认网卡` 那一行地址）。
注意启动脚本里 `--host 0.0.0.0` 才是"局域网可访问"，`127.0.0.1` 只有本机能连。

**Q：数据存在哪？怎么重置？**
`project/backend/data/coc.db`（房间 / 消息 / 角色卡 / 模组 / 存档全在里面），
密钥在 `project/backend/.env`，两者都不入 git。
想推倒重来：删掉 `coc.db` 后跑 `python -X utf8 scripts/init_db.py`（会重新灌种子数据）。
只想清房间数据：在游戏里「结束游戏 / 解散房间」。

**Q：怎么停服务？**
在启动窗口按 `Ctrl + C`。

**Q：改了后端代码要重启吗？**
`start.bat` 起的服务没有 `--reload`，改完手动 Ctrl+C 再启动一次；开发模式（第 5 节）用的是 `--reload`，会自动重载。

## 7. 演示前检查清单

```bat
:: 1. 一行自检（环境 / 依赖 / 数据库 / 前端产物）
start.bat --check

:: 2. 起服务 + 开浏览器，走一遍：建房 → 加入 → 发消息 → 掷骰 → 存档
start.bat
```

- [ ] `--check` 五步全过，没有 `[X]` 或 `[!]`
- [ ] 大厅顶部**没有**引导条（说明模型已配好），或已点过「启用演示模式」
- [ ] 用第二台设备（手机 / 另一台电脑）验证局域网地址能打开
- [ ] 设置面板里「测试连通」有延迟返回（演示模式可跳过）
- [ ] 有一个可用的角色卡（或现场用向导建一张，约 1 分钟）
- [ ] 知道「结束游戏」在哪（左侧/顶栏），演示完能干净收场
